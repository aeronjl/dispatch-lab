# Revisit an original investigation choice

`recorded-investigation-alternatives/1` adds **Inspect first or intervene directly** to the revealed Site services comparison. It is available at a decision with a saved, resolved investigation selection. Later intervals offer a return to that original selection. Playback pauses; closing the comparison returns keyboard focus to its opening control.

The alternative changes the selected strategy within the original bounded comparison: a compatible inspection and finding-dependent remedy, or direct qualified module replacement. Both strategies are recalculated under the same original information and current implementation. The original prediction remains separately readable. This does not replay a completed run with its later realised weather, infer an unrecorded fault, or change the original work orders.

## Original information boundary

Preparation reads only the selected decision's pre-selection snapshot, catalogue, proposed inspection, conditional calculation inputs and policy. It checks the saved identities, hourly boundary, original plant/state/forecast/prices and declared prior. The enclosing episode is excluded: later findings, procedure receipts, confirmation times and post-intervention beliefs are not inputs to this comparison. Repriced reports are not dispatch assumptions.

The saved snapshot preserves already accepted work, observed cursors, isolation, stock reservations, support availability and eligible measurements. The comparison occurs before the service controller's subsequent selection of new work/charging. It does not claim to reproduce that later joint selection. Original future capacity commitments unsupported by the conditional planner remain an explicit incomplete result; they are never silently removed.

Only the supported strategy identifier and original selection identity cross the user-input port. Inputs cannot replace the original forecast, probability weights, prices or capabilities. An older archive without the required original calculation remains unavailable; current documentation does not reconstruct missing evidence. A later hour must first return to its actual selection boundary. An originally unresolved choice has no selected baseline to replace.

## Prediction and accounting

The adapter reuses the conditional work, scenario process planner, operating-limit validation, service-cost pooling and static contact likelihoods already used by the recorded selector. It does not introduce a second physical model. A repair's hypothetical restoration changes possible delivered capacity; requested controls remain equal until eligible observations distinguish branches. Future operating tests remain predictions requiring actual evidence before confirmation.

Both columns show probability-weighted methane, starts, ending plant inventories and temperature, incremental service/total decision costs and assumed operating contribution. Expected starts and inventories are statistics, not a single executable trajectory. Every possible branch retains its own thermal sequence, test window, physical hypothesis, conditional ending service stocks, unselected requests and unresolved retrieval/readiness obligations.

All positive-probability branches must be feasible before an expected aggregate is shown. Incomplete branches are not dropped or renormalized. A fully calculated strategy can still fail the original minimum restoration-probability requirement; that ineligibility remains visible. Fixed ownership and already incurred costs are excluded from decision incentives, with no speculative terminal sale proceeds or duplicate production-loss penalty.

The UI shows termination, incumbent validity, gap, source changes, original forecast availability, original price identities and assumed risk weight. It does not require the replan to reproduce a previous finite-time solver incumbent or claim a global optimum. Scenario probabilities remain illustrative, and operating recovery remains unverified in all prediction branches.

## Transport and preservation

The existing service-comparison endpoint dispatches this separate adapter in an isolated, bounded worker. It retains cancellation, progress, wall-clock expiry and ownership by run/controller/decision/client generation. Changing inputs, closing the comparison or moving the playhead invalidates the older response; a previous valid result stays labelled as belonging to earlier inputs when appropriate.

The completed source run and its recorded predictions remain immutable. The calculation response contains the original packet identity, original selection identity, current/original source identities, recorded comparison and new conditional result. Existing archives keep their saved explanations and earlier alternative behaviour. Offline playback continues to disclose that live recalculation requires a restored application.

This completes the original-selection alternative within the bounded investigation model. Replanning a later, ongoing investigation under its post-intervention belief is a different control problem and is not misrepresented as this initial choice. The wider six-stage field programme, complete service essays, hardware families and learned-policy evaluations remain open.

## Cold archive loading finding

The recorded walkthrough exposed an existing Gradio HTML configuration collision. In the installed version, `HTML.__getattr__` treats any quoted word in `js_on_load` as a potential custom event. The unset `inputs` constructor attribute therefore became a `functools.partial` bound to the scene when that word occurred in the browser code. The root route's configuration deepcopy followed the binding back into the entire Blocks and archived-state graph. A 164.5 MB decoded archive produced repeated local readiness timeouts even with a diagnostic 30-second allowance.

The scene now explicitly sets its non-reactive `inputs` attribute to `None`. Custom application events remain intact, the browser configuration contains no accidental bound input callback, and no installed dependency or readiness validation is bypassed. Separately, the profiled cold construction spent 35.6 seconds in Gradio State initialization and 8.5 seconds preparing an initial export; those costs are not claimed solved by the configuration fix. They remain a candidate for a separate bounded archive-handle/on-demand export improvement after the real walkthrough passes.
