# From an observed finding to an operating test

Opt-in `observed-service-investigation/2` links the bounded investigation comparison to `scheduled-load-tests/2`. This extends the service/production planning stage; it does not complete the full field-operations programme.

## Timing and information

The comparison uses the operating observer's next bounded upward test load, rather than always requesting full nameplate capacity. `inspection-contingency-planning/2` records this load in every branch. The original version-1 comparison keeps its full-nameplate semantics. A successful-delivery hypothesis remains a prediction and cannot upgrade the observer.

After an actual eligible finding commissions compatible work, `observed-investigation-continuation/1` checks all positive-probability branches for that finding. They must agree on the remedy, test duration, requested load and original test start. Private repair success cannot select a convenient branch. The immutable continuation retains those branch identities, the original comparison, actual evidence, actual work order and original investigation deadline. Unavailable evidence, a different finding or disagreement leaves the continuation unresolved.

The nominated test is not yet an accepted window. Each joint service candidate must include the required intervention, retain its already accepted commitment, or have an eligible actual completion receipt. The earliest test boundary is the next hourly decision after the complete mission return. A shared crew itinerary includes later jobs and the whole journey. Future planned return times never become observed receipts. Failed work cannot authorise its old post-return test.

Only a validated combined work, charging and process candidate is accepted. The investigation view records its absolute start/end, requested load, return prerequisite and deadline. If actual finding time, work or resources change the original predicted window, the operating record says so. An accepted window still does not establish recovery. Consecutive real electrical and inventory observations are required.

The independent recovery episode may have an earlier deadline than the investigation; the joint request retains the earlier boundary. A missed test deadline is reported, not silently moved. The investigation's own deadline never restarts with later interventions. These two episode boundaries are visible and must not be compared as identical metrics to the version-1 rolling scheduler.

## Follow-up after an intervention

An observed interruption or distinct eligible, resource-feasible tracking shortfalls can justify another bounded qualified intervention. That continuation explicitly says `observed-follow-up` and has no reconstructed conditional branch or predicted start. It retains the original investigation deadline and attempt limits. The original static prior is not applied again after intervention. Version 3 optionally adds [declared post-intervention belief transitions](recovery-belief.md) and a further probability gate for additional work. Those illustrative probabilities remain uncalibrated; operating recovery confirmation stays separate.

## Preservation, UI and alternatives

Planning snapshot version 3 captures public work receipts and observed shared-visit returns once at the original decision boundary. Restored adapters expose only those saved observations; they cannot execute work. Version-1/2 snapshots still load without migration and explicitly lack uncaptured receipts. A planned route is not used to fill that gap.

Advanced field setup reveals the investigation editor only when coordinated services are enabled. Custom recorded priors survive edits to the supported controls. Site services reveals the nominated and accepted test with the investigation episode. No plant artwork or labels change. Process and service what-ifs retain the original work prerequisite, accepted test and deadlines. They remain predictions based on the saved information and cannot change the completed run. Selecting a different investigation strategy in a what-if is not yet supported.

## Reproducible workflow examples

Run a new edition with:

```sh
.venv/bin/python -m methane.services.continuation_examples --directory build/services/my-continuation-edition
```

The writer refuses a nonempty destination. Six 32-hour, seed-7 cases include matched trip and damaged-equipment pairs, unreadable evidence and a power shortage. Each saves numerical results, full evidence and inventories, animated playback and a source-restorable offline bundle. The pairs compare policy packages: bounded conditional tests and joint acceptance change together. They are not an isolated one-parameter ablation. Sensors are noiseless and compatible-procedure probabilities illustrative. Interpret solver limits, unfinished work, ending health and finite-window feedstock constraints before ranking methane totals.

Automated checks cover branch consensus, future evidence, failed work, follow-up justification, actual findings, shared returns, archive boundaries, original-information alternatives and physical reconciliation. Reviewed results and any numerical reproduction differences belong to the edition's report; this mechanism description makes no general performance or empirical reliability claim.
