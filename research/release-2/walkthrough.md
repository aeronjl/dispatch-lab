# Comprehension walkthrough

This is an agent-authored inspection of the implemented workflow and automated
interaction evidence. No participant study has been performed. It cannot establish
that an unfamiliar user understands the platform.

## Tasks and the distinction the interface must make

1. Open Sites from the quiet simulation menu. Select a saved European environment,
   open a design and reveal Deployment and maintenance. Apply an illustrative
   preset, inspect its assumptions and save a new design. The existing physical
   run is unchanged until a new study executes that design.
2. Enter Model from that panel. Follow mobilisation, installation, acceptance and
   departure in the deployment essay. The diagram's current phase and its capacity
   plot use the same example. Acceptance at the end of an interval makes capacity
   available at the next boundary. Equipment departure is a separate event.
3. In the condition essay, change exposure and observation delay. Private physical
   condition, the delayed reading, the current estimate, replacement work and
   confirmation are separately labelled. A completed procedure does not itself
   establish restored condition. The fixture fixes operating activity and is not
   a remaining-life prediction.
4. Select an unsupported hardware family. Declaring its prerequisites still does
   not create an executable mechanism. Human module replacement and prepared
   installation are bounded capabilities; neither establishes autonomous insertion.
5. Calculate maintenance alternatives. Keep the same weather and initial condition;
   compare ending inventories, consumed parts and work alongside methane. These are
   learning examples with illustrative rates, not modifications of the selected run.
6. Return to a saved lifecycle run, reveal the electrolyser inspector, and follow
   Condition & maintenance / Commissioning record. This run shows the original
   decision and recorded interval with retrospective condition explicitly separated.
   Escape restores the component, playhead and invoking button's focus.
7. Read the matched study at more than one boundary. A larger final methane total
   can accompany depleted stocks, expensive consumed parts or unresolved work.
   Recognise missing quotations and the distinction between allocated costs,
   actual modelled expenditure and a dispatch contribution.
8. Open the reproduction bundle offline. Recorded playback, original Model pages
   and independently checked numerical traces are available without a network.
   A new numerical edition has its own archive and comparison; it is not playback.

## Misunderstandings and implementation findings

These observations are separate from automated pass/fail counts.

- An early deployment illustration could be read as showing accepted capacity
  during the work interval. The reviewed implementation uses beginning-of-interval
  phase data and separately records the ending package state.
- Hardware prerequisites are categories. Plotting them as a time trajectory would
  imply an unmodelled progression; the hardware essay now uses named prerequisite
  states and an eligibility explanation.
- A full-array condition is an intentionally homogeneous model. A half-installed
  plant does not thereby become a spatially resolved population of differently
  aged modules. The assumption is explicit in the contract and report.
- A zero residual at a low load is easy to overread as full health. The controlled
  experiment documents two capacities with identical observations below their
  shared feasible load; upward probes are needed for stronger claims.
- A modelled procedure can be complete while its confirmation remains unavailable.
  Estimates persist until an eligible post-procedure reading; no success label is
  supplied by the private outcome alone.
- The new catalogue's additional parameters exposed an old browser count expectation.
  That expectation was updated after checking the registry; it was not a missing UI
  parameter. The four new essay images received separate reviewed baselines.
- Test authors initially addressed a hidden scrubber and the context caption rather
  than the visible context selector. The corrected tests use the actual disclosure
  flow and assert the original controller/interval. These were test-author mistakes,
  not evidence of participant confusion.

## Participant questions for Release 3

Ask unfamiliar users to explain a mechanism, find an assumption, trace a result,
state what evidence does and does not establish, identify an unconfirmed repair,
and return to the original simulation. Record their words and misinterpretations
separately from task completion and automated tests. Prioritise any confusion
between predictions, observations, estimates and retrospective truth before
introducing learned-policy explanations.

The corrected-source browser run also exposed an overly short test deadline for
an explicit maintenance comparison under heavy background work. The captured
requests showed responsive progress through the fourth rule while the 20-second
assertion expired. The comparison-control test now allows 60 seconds for that
explicit worker; the simple-example performance limits were not changed. Its first
failed attempt and the complete rerun are separate receipts. This is a test timing
finding, not a participant observation or a claim that long calculations are instant.

The weekly comparisons expose a reporting trap: the periodic rule first becomes
due at H168, exactly after the short run ends. Its baseline-identical totals do not
establish that preventive maintenance is ineffective. The report now states this
exposure boundary beside the findings; the annual and teaching cases exercise work
after a due date. The original protocol inputs and completed results are unchanged.
